### Changed
- Upstream submodule bumped from the release tag v0.4.1 (02f0a97) to **v0.5.1** (6478508, 2026-09-28): 14 upstream commits — package updates, generation-artifact removal, per-service `mistralai` pins, licensing cleanup. Directory layout, Helm scaffold charts, frontend contract and the dokumentenaufbereitung schema are unchanged (README A/B/C).
- Build pipeline: the dokumentenschwaerzung orchestrator and PDF-PII detector build their test-deps stage from `uv:0.9.30-python3.12-bookworm-slim` pinned by tag **and** digest (upstream's placeholder suffix is the ghcr.io index digest, verified); `pipeline/base-image-map.env` rows now also rewrite bare `FROM` lines, so the frontend (`node:20-bookworm`, `nginxinc/nginx-unprivileged:1.29-alpine`), request-proxy and ki-guv-feedback (`python:3.12-*`) pull from public.ecr.aws instead of Docker Hub. All 24 upstream contexts lock with `uv lock` (mistralai 1.12.4 for norm-matching, rechtsquellenvorbereitung, risikohinweis, subsumtion).
- Verified live 2026-10-20 with `make bootstrap` from zero (220 + 4 resources, 25 images, cold image batch about 20 min): `scripts/verify.sh` 6/6 green, scripted OIDC login, Vollstaendigkeitspruefung `ENTWURF` with 2 of 3 Soll-Dokumente matched, Kohaerenzpruefung with Plausibilitaet **and** Konsistenz `ENTWURF` and Hinweise — twice in a row; 72 signed decision steps stored in `decision_log_store` by the decision log store, none dead-lettered; 57 Claude Haiku + 49 gpt-oss Bedrock invocations in the hour (README C/G).
- dokumentenpruefung's default model is the structured-output alias (`LLM_DEFAULT_MODEL="<LLM_MODEL>"`): v0.5.1 dropped the per-prompt model override, so the service default decides every check call (README C).

### Fixed
- Cold-start regressions found on the first v0.5.1 bootstrap and fixed in the deployment layer: frontend `npm ci` rejects the v0.5.1 lock on npm 10 (npm 11 pinned in the builder stage); SQLAlchemy 2.1 and FastAPI 0.145 broke six services at import (resolver constraints `sqlalchemy<2.1`, `fastapi<0.145`); `NoOpLogger.setLevel` missing for dokumentenpruefung (shim on the vendored bizlog); dokumentenpruefung's decision-step helper vs. decision-protocol v0.5.1 (non-UUID fallback dropped, anchorless steps skipped); berichtskonfigurator bound to the loopback address (`HOST=0.0.0.0`); ner-extraction `INFERENCE_*` rename and `PROMPT_LANG`; dokumentenaufbereitung-monorepo `EMBEDDING_MODEL(_REVISION)`. Each with the observed error in README A/C.

### Added
- Optional corporate identity provider in front of every page: with `EXTERNAL_OIDC_ISSUER_URL`/`_CLIENT_ID`/`_CLIENT_SECRET` set in the root `.env` (any OIDC issuer), oauth2-proxy authenticates against that issuer instead of the demo Keycloak and the Keycloak host is fenced behind the same check, so an anonymous visitor gets nothing but a redirect to the issuer. Empty = unchanged demo login. Values live in a Secrets Manager entry (`…/auth/external-oidc`), nothing provider-specific in the repository (README "Auth perimeter", THREAT-MODEL E-13).
- `decision-log-store-service` (new upstream service at v0.5.1): built, deployed and wired — own database `decision_log_store` (13th, created by db-init), consumes the signed audit/decision events from `bizlog_exchange` and verifies them with the bizlog signing key (`HMAC_SIGNING_KEY`).
- bizlog audit routing: every bizlog consumer (14 enabled services) now publishes signed audit/decision events to RabbitMQ (durable topology, dedicated audit route to the decision log store) instead of fallback-only local logging; ordinary business events stay on stdout. `rabbitmq-init` declares the producer-owned `bizlog_exchange` so the consumer is Ready at cold start. Closes THREAT-MODEL R-6 as an open finding (now Low).

### Removed
- `BIZLOG_AUDIT_ENDPOINT` and `BIZLOG_EVENT_VERSION` from the wiring matrix where the v0.5.1 shared lib is the only reader (the two dokumentenaufbereitung services keep them: their own config still declares them as required); the duplicate `BIZLOG_AUDIT_SIGNING_KEY` keys of three service blocks.

### Security
- Non-production disclaimer in the first screen of the README (and the root README), linking the threat model.
- `auth_enabled=false` is refused by Terraform unless `allowed_cidrs` (`DEMO_ALLOWED_CIDRS`) is non-empty (`terraform_data.perimeter_guard` precondition): no OIDC perimeter plus an open NLB would expose every service anonymously.
- Keycloak admin deny matches the normalized `$uri` (percent-decoded, `//` merged, dot segments resolved) instead of the raw `$request_uri`; `scripts/verify.sh` probes encoded, double-slash and dot-segment spellings with `--path-as-is` and expects 403, and 401 (not 403) for the realm admin REST API. Platform chart 0.2.0.
- `BEDROCK_REGION` default aligned to `eu-central-1` (Terraform variable and chart default; was `us-west-2`): a Bedrock region other than `AWS_REGION` moves prompts and document content across a region boundary and is now an explicit choice.
- One customer-managed KMS key per environment (`terraform/modules/kms`, rotation on, 7-day deletion window) encrypts every Secrets Manager entry, the documents and build source buckets (SSE-KMS + Bucket Keys), every ECR repository, the CodeBuild project and its log group, RDS Performance Insights and the exported RDS log groups. ESO is limited to `kms:Decrypt` on that key; the CodeBuild role and the S3 IAM user receive the matching key permissions.
- ECR repositories are IMMUTABLE with scan-on-push and KMS encryption; the buildspecs no longer push `:latest` and skip an image whose content tag already exists (`aws ecr describe-images`, `ecr:DescribeImages` added to the role). The Makefile refuses `plan`/`apply`/`bootstrap` when no image tag resolves instead of falling back to `latest`.
- CodeBuild log group: 365-day retention, KMS; `ecr:GetAuthorizationToken` isolated in its own policy so no wildcard resource shares a statement list with data access; `arn:aws:` prefixes replaced by the partition data source.
- S3: versioning + lifecycle (7-day noncurrent expiry, abandoned multipart cleanup) on the documents and source buckets.
- RDS: log exports into pre-created KMS-encrypted log groups (365 days), Performance Insights, Enhanced Monitoring, IAM auth (additive), `copy_tags_to_snapshot`; `deletion_protection` variable (`SPARK_API_RDS_DELETION_PROTECTION`, default false).
- EKS public API endpoint honours `DEMO_ALLOWED_CIDRS`; Terraform registry modules pinned to release-tag commits; availability zones pinned by name.
- TEI `BAAI/bge-m3` pinned to a Hub revision; inspector base image pinned by digest with a `HEALTHCHECK`.
- Inspector backend (`inspector/app/main.py`): a failing source (LiteLLM, RabbitMQ, CloudWatch) no longer streams the exception text to the browser (CodeQL `py/stack-trace-exposure`, CWE-209: httpx errors carry the internal service URL, botocore errors the caller ARN and account ID). The SSE event now carries one of nine constant categories (`unreachable`, `timed out`, `authentication failed`, `upstream error`, `request rejected`, `access denied`, `aws api error`, `aws client error`, `unavailable`); the full exception with traceback goes to the pod log, once per distinct failure and once on recovery instead of every 5-second poll. Verified with a test that drives the real stream with failing pollers (no secret substring in the stream, all of them in the log).
- Inspector overlay (`inspector.js`) renders with DOM nodes and `textContent` only — no `innerHTML` with request paths, model/queue names or backend error text (semgrep `insecure-innerhtml`, verified with a DOM-shim test feeding hostile strings through every render path).
- `scripts/push-source.sh`: boolean flag expansions quoted.
- Static review (checkov + semgrep) brought to zero findings; every remaining trade-off carries an inline `#checkov:skip` / `# nosemgrep` with its reason (privileged CodeBuild for `docker build`, single-AZ RDS, no secret rotation, no bucket access logging/replication, static S3 keys, demo-grade teardown flags).
- Internal process and tooling references removed from the published tree (Makefile note, scanner wording in the auth ingress comment, README and this changelog).

### Security (earlier)
- Keycloak admin surface no longer answers from the internet: `/admin/master/**` (the console for every realm) and `/realms/master/**` return 403 at the edge (nginx `server-snippet` on the Keycloak Ingress). Driven by a security scan of the live deploy — the master realm's admin console was reachable with only the generated bootstrap password in front of it. Scope stops short of `/admin` on purpose: the token-protected admin REST API lives under `/admin/realms/<realm>` and services call it through the public hostname. Verified live: console/master 403, `/admin/realms/local/users` 401, login discovery 200, full scripted OIDC login green
- Optional source-IP allowlist on the public NLB: `DEMO_ALLOWED_CIDRS` (root `.env`, comma-separated) → `loadBalancerSourceRanges` on the ingress-nginx Service, covering every hostname and both `:80`/`:443`. Empty = open to the internet (unchanged from-zero default). An nginx-level allowlist cannot work here — with NLB `ip` targets and `use-proxy-protocol=false` nginx never sees the client address

### Fixed
- `make bootstrap` from zero completes again: the `data-service-schema-seed` hook crash-looped into `BackoffLimitExceeded` and aborted the whole bootstrap. Root cause is a cold-start table race in the database the two `dokumentenaufbereitung` services share — on a fresh DB the monorepo's startup migrations can create `doc` without the mock-only `deleted` boolean and `chunk_metadata` with `labels` as `text[]` instead of `varchar` (observed: `UndefinedColumnError "column doc.deleted does not exist"`, then `DatatypeMismatchError`). The seed now reconciles `doc.deleted` and a default for the monorepo's `NOT NULL upload_date` before touching any mock model, and writes chunk rows through casted SQL (with an explicit `flush()`, since raw statements bypass the ORM's insert ordering) when it detects the monorepo shape
- Materielle-Pruefung match jobs now run through the real pipeline (document selection → Antragstyp identification → chunk retrieval) instead of failing instantly: seeded documents carry `document_type: Antrag` (norm-matching selects candidates by that type; observed: "No document IDs provided") and the data-service seed adds one page + chunk-metadata row per demo document (observed: "No chunks found for provided 2 document IDs").
